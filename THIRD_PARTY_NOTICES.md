# Third-party notices and parameter attribution

## MOPAC PM7 data and reference formulas

The PM7, PM7-TS, PM7-, PM7-HH, and Sparkle parameter tables in `src/data/pm7*.csv` are generated by `tools/extract_params/extract_pm7.py` from the MOPAC v23.2.5 source tree, pinned at commit `052691223d19935a89f0fe18cd12301bd83e4201`.

The extraction preserves MOPAC's per-element values, pair `ALPB`/`XFAC` constants, `VPAR` entries, Gaussian core-core terms, isolated-atom data, and Sparkle table.

The retained MOPAC license is at `third_party/mopac/LICENSE`.

The following source modules are Rust translations of the corresponding MOPAC v23.2.5 routines (Apache-2.0, © 2021 Virginia Tech), with each MOPAC source file named in the module doc-comment. No numeric parameter is changed; the ports transcribe the published semiempirical formulas:

- `src/repulsion.rs` — PM7 core-core repulsion (`src/integrals/ccrep.F90`).
- `src/mndod.rs`, `src/mndod_twocenter.rs`, `src/mndod_tables.rs` — MNDO/d one- and two-center integral machinery (`src/integrals/mndod.F90`, `mndod_C.F90`, `rotate.F90`); the index/coefficient tables are mechanically generated by `tools/extract_params/gen_mndod_tables.py`.
- `src/overlap_d.rs` — d-orbital diatomic Slater overlaps (`src/integrals/{diat,coe,bfn}.F90`).
- `src/dispersion.rs` — PM7 post-SCF dispersion (`src/corrections/H_bond_correction_PM6_DH_Dispersion.F90`); references Korth, Pitoňák, Řezáč & Hobza, *J. Chem. Theory Comput.* **6**, 344 (2010).
- `src/hbond.rs` — PM7 post-SCF hydrogen-bond correction ("EH+"), from `src/corrections/Hydrogen_bond_corrections.F90` (`all_h_bonds`/`find_XH_bonds`/`find_H__Y_bonds`/`setup_DH_Plus`), `H_bond_correction_bits.F90`, and `H_bond_correction_EH_plus.F90`, with the geometry primitives `src/geometry/{bangle,dihed,dang}.F90`; references M. Korth, *J. Chem. Theory Comput.* **6**, 3808 (2010).
- `src/hh_rep.rs` — PM7-HH hydrogen–hydrogen repulsion (`src/corrections/` `energy_corr_hh_rep`).
- Sparkle `eheat_sparkles` reference heats in `src/params.rs` are from `src/models/parameters_C.F90`.
- `src/field.rs` — the uniform external electric field, in MOPAC's `FIELD=(x,y,z)` volts/Ångström
  convention and sign: the one-electron terms and the nuclear term from
  `src/integrals/hcore.F90:143-208`, and the closed-form gradient `∂E/∂R_A = q_A f` from
  `src/forces/dfield.F90:45-55`.
- `src/dipole.rs` — the NDDO dipole operator: the point-charge term, the one-centre s–p
  hybridization term, and the one-centre **p–d** term with MOPAC's `ddp(5)` charge separation and
  its `±1, ∓1/√3, +2/√3` coefficients, from `src/properties/dipole.F90:96-152`. The
  centre-of-mass recentring of a charged species follows the same file (`:86-103`).
- `src/ir.rs` — the vibrational-dipole quantities MOPAC prints under `FORCE LARGE`
  (`DIPX`/`DIPY`/`DIPZ`/`DIPT`), from `src/forces/force.F90:405-441`, including the factor of one
  half its finite-difference definition carries (`src/forces/fmat.F90:197-252`). Reproduced so the
  two programs' output is directly comparable; see `docs/fidelity.md`.

The PM7 **core** Klopman–Ohno radius `po(9)` (the `poc`/`pocord` parameter, used by the
core–core repulsion and electron–core attraction, distinct from the electron-cloud `rho0`
used by the electron–electron integrals) follows `src/integrals/mndod.F90` and
`src/models/calpar.F90`.

The MNDO/d formalism is due to W. Thiel & A. A. Voityuk, *Theor. Chim. Acta* **81**, 391 (1992); *J. Phys. Chem.* **100**, 616 (1996).

- Release used for validation: <https://github.com/openmopac/mopac/releases/tag/v23.2.5>
- Upstream license: Apache-2.0

PM7 is described by J. J. P. Stewart, *J. Mol. Model.* **19**, 1 (2013).  Parameter values and scientific formulas remain attributable to their original authors.

### Periodic boundary conditions

The periodic implementation was written against the same pinned MOPAC v23.2.5 tree, chiefly for
the MOPAC-compatibility mode, which reproduces MOPAC's own solid-state numbers rather than being
an independent formulation:

- `src/pbc/trunc.rs` — MOPAC's truncated image sum, its asymmetric treatment of `J` (all images)
  versus `K` (nearest image only), and the `trunk`/`derp` distance compression
  (`src/SCF/hcore.F90:220-233`, `src/integrals/solrot.F90:75-105`, `src/derivatives/dcart.F90:459-501`).
- `src/pbc/kpoints.rs`, `src/scf_pbc.rs` — the Born–von Kármán supercell construction MOPAC builds
  with `makpol` (`src/makpol/*`), used here as the equivalence a k mesh is tested against rather
  than as the sampling method itself.
- `src/hamiltonian.rs` — the image-pair enumeration follows `hcore.F90`'s translation loop.

The Ewald mode (`src/pbc/ewald.rs`) is not derived from MOPAC, which has no Ewald summation. Its
1-D wire kernel and 2-D Parry/Heyes sheet kernel follow the standard literature treatments; the
decomposition it rests on — that beyond 7 Å every PM7 two-centre integral is *identically* the
point-charge monopole — is a property of PM7's own feathering, read from
`src/integrals/mndod.F90` (`to_point`) and `solrot.F90` (`nddo_to_point`).

## Rust dependencies linked into the shipped binaries

The full notice is `third_party/rust/NOTICES.md`, generated by
`tools/licenses/collect_rust_notices.py` from the resolved dependency graph.

The MOPAC attribution above is about *source* this project derived from. This section is about
something separate that is easy to miss precisely because no source file records it: `cargo build`
links statically, so `pm7_rs_cli` and the `pm7_rs._native` extension inside the wheel are each a
copy of a substantial portion of roughly 120 crates. MIT requires its copyright and permission
notice in "all copies or substantial portions of the Software"; Apache-2.0 requires the same by
sections 4(a) and 4(b). Through 0.2.2 neither binary carried any of it. The crate list, the
copyright holders and the verbatim license texts are all in that file.

Three things about it are worth stating here rather than leaving in a generated table:

- **The texts are read from the crate sources, not reconstructed from the SPDX identifier.** That
  is what turned up the case the identifier hides: `faer`'s manifest says `MIT`, and the crate
  additionally ships `COPYING.EIGEN.MPL2`, `COPYING.LAPACK.BSD`, `COPYING.SUITE_SPARSE.AMD.BSD` and
  `COPYING.SUITE_SPARSE.COLAMD.BSD` for algorithms ported from Eigen, LAPACK and SuiteSparse. A
  notice generated from manifest metadata alone would have said "MIT" and dropped an MPL-2.0
  obligation. `faer` is this project's dense linear algebra, so those files are in every binary.
- **The list is the union over every target platform**, not the one that built it. A third of these
  crates are platform-gated, and a per-host notice would give each wheel a different list that no
  other machine can check.
- **Development-only dependencies are excluded** — `criterion` and its tree are in no released
  artifact — and the dependency-graph walk decides that, not a hand-kept list.

The direct dependencies are `faer`, `rayon` and `pyo3` (the last only under the `python` feature);
everything else in that file is transitive.

The wheel carries all of this in `dist-info/licenses/`, which `pyproject.toml`'s `license-files`
arranges and `tests/attribution.rs` checks. **A binary-only archive has to carry it too**: an
archive containing `pm7_rs_cli.exe` and nothing else does not satisfy either license, so
`LICENSE`, this file, `third_party/mopac/LICENSE` and `third_party/rust/NOTICES.md` go into the
release archive alongside the executable.

`serde`, `serde_json` and `clap` are in `Cargo.lock` and deliberately **not** in the notice. They
reach the lock file only as dependencies of `criterion`, which is a `[dev-dependencies]` entry used
by `benches/scaling.rs`; no released binary contains them, and neither the argument parsing in
`src/bin/pm7_rs.rs` nor the JSON writing uses them. Being in the lock file is not the same as being
in the artifact, and a notice that listed everything in the lock would be claiming to redistribute
code it does not ship.

## Removed material

This repository no longer distributes AM1-BCC/AmberTools parameters or topology code.  No AM1-BCC notice applies to the current source tree.

Through v0.2.2 this file carried a PySEQM notice, and `third_party/` held a BSD-3-Clause license
for it.  Both are removed in 0.2.3, and the reason is worth stating rather than leaving to be
re-litigated.

PySEQM implements MNDO, AM1 and PM3; it does not implement PM7.  Every NDDO routine here — the
overlaps, the multipole integrals, the Fock assembly, the two-centre machinery, every parameter —
is a translation of MOPAC v23.2.5, named file by file in the section above, and `tests/` pins the
numbers against MOPAC rather than against PySEQM.

What the old notice claimed was "implementation ideas", and that is the accurate description of
what remained: two conventions in `src/integrals.rs` — the shortest-arc quaternion for the
two-centre frame, and the sign of the local axis — that the author took from reading PySEQM.  The
quaternion is a standard construction that predates PySEQM, and a frame sign is a choice with two
options; neither is copyrightable expression, so neither requires a BSD-3-Clause notice.  Both
comments now describe the construction and cite the MOPAC routine they are checked against.

A notice naming an upstream this code does not descend from is not a courtesy — it sends anyone
verifying a formula to the wrong source.
